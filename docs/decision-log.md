# 決策紀錄

- 2026-10-20 運維流程轉成五支選單腳本（`install.sh`、`backup.sh`、`upgrade.sh`、`nginx.sh`、`network.sh`），不用線性 wizard — 這些是會重複執行的維運動作，選單可隨時挑任一項。
- 2026-10-20 腳本全自動執行並冪等寫入 `gitlab.rb` 管理區塊，不再開 `nano` — 要的是互動式腳本，不是講義。
- 2026-10-20 每次改 `gitlab.rb` 前備份為 `gitlab.rb.bak-<時間戳>`，`reconfigure` 失敗時詢問是否還原 — 改壞設定後 GitLab 無法重新配置。
- 2026-10-20 參數以詢問取得、答案存入 `scripts/gitlab-ops.env`；LDAP bind 密碼只隱藏輸入、不落檔 — 重跑省重打，但密碼不外洩到參數檔。
- 2026-10-20 設定備份以 `gitlab-ctl backup-etc` 為準，改寫並改名 `gitlab_backup.sh` 為 `backup_auto.sh`（cron、升級前、選單「立即備份」共用）— 原腳本只 tar 三個檔案，漏掉 `trusted-certs` 等。
- 2026-10-20 外部 Nginx 全流程歸 `nginx.sh`，`install.sh` 不再重複；`external_users` 讀 `nginx.conf` 的 `user` 偵測 — 01 寫 `www-data`、04 寫 `nginx`，兩份文件互相矛盾。
- 2026-10-20 自簽憑證共用 `common.sh` 的 `make_self_signed_cert`，加 `subjectAltName` 並用 `-subj` — 只有 CN 的憑證現代瀏覽器會報錯；偏離原文件。
- 2026-10-20 `upgrade.sh` 吃一個依序放 `.deb` 的資料夾，逐版升級並輪詢背景遷移歸零，已裝版本以下的檔案略過 — 允許中斷後接續；「該停哪些版本」仍由人查 Upgrade Path Tool。
- 2026-10-20 `network.sh` 只提醒 IP 變更後 `external_url`、憑證、`server_name` 需同步，不自動連動修改 — 改 IP 罕見，自動連動牽涉過廣。
- 2026-10-20 腳本完成後刪除 `docs/01`～`05`，全部內容（前置條件、注意事項、故障排查表、切換回內建 Nginx 等）併入對應腳本，各腳本以選單項目「說明」「常見問題排查」呈現；README 改指向腳本 — 單一事實來源，文件與腳本不再漂移（取代先前「文件縮成說明」的決定）。刪除須在腳本實作並試跑通過之後。
- 2026-10-20 驗證採 `bash -n`、`shellcheck`、純函式的 bash 測試；`dpkg`／`netplan` 等真實動作靠 Ubuntu VM 試跑，不宣稱已驗證 — 本機為 Windows。
- 2026-10-20 `network.sh` 與 `install.sh` 的安裝動作的機器檢查只要求 Ubuntu 工具，不要求 `/opt/gitlab`（`network.sh` 為 `apt`、`netplan`、`ip`；`install.sh` 的 `dpkg -i` 前為 `require_machine ubuntu dpkg`）；`require_machine` 以機器角色（`online`/`server`/`ubuntu`）命名 — 固定 IP 與安裝 `.deb` 都發生在 GitLab 安裝之前，偏離 PR-COM-04 字面（環境不符時中止並說明應在哪台執行仍成立）。安裝後才有意義的動作（改 `gitlab.rb`、讀初始密碼）仍用 `server` 角色。
- 2026-10-20 PR-INS-05 視為 PR-COM-06 的唯一例外，只涵蓋 `initial_root_password` 那一行：它是 GitLab 產生、24 小時失效的一次性初始密碼；不寫參數檔、日誌、命令列，解析失敗退回請 `sudo cat` 該檔；LDAP bind 密碼不適用此例外 — 不顯示就沒辦法登入，但仍把露出面降到最小。
- 2026-10-20 `nginx.sh` 三項防呆偏離 04 文件：相依錯誤解析 `dpkg -i` 自身輸出而非 `dpkg -l | grep nginx`（後者漏掉非 nginx 名稱的相依）、來源行寫死 noble 故 codename 必須為 noble、下載前確認 `apt-cache policy nginx` 的候選版本來自 nginx.org（避免打包到 Ubuntu 自家 nginx）。
- 2026-10-21 CI 用 GitLab Runner，與 GitLab 同機（POC）、Docker executor、instance runner、不開特權；新增 `scripts/runner.sh` 選單腳本，機器角色沿用 `server` — 同機會搶資源，故 `concurrent` 預設 1、安裝前警告磁碟剩餘低於 20 GB，不排自動清理 cron；POC 求簡單，日後要隔離再改專用 Runner 主機。
- 2026-10-21 Runner 版本與 GitLab 版本不一致時警告並詢問，不硬擋；token 由使用者在後台建立後隱藏輸入貼上，不用管理員 PAT 自動建立 — 不多持有一個高權限秘密。
- 2026-10-21 job 容器以 `clone_url` 指向區網 IP 連回 GitLab（不用 host 網路），HTTPS 時複製 CA 到 `/etc/gitlab-runner/certs/` — 容器內的 127.0.0.1 是容器自己；離線 image 預設 alpine:3.20、ubuntu:24.04、node:22、python:3.13、docker:27-cli，可由 `ask_param` 改。
- 2026-10-21 POC 的 `external_url` 為自簽憑證 HTTPS：Runner 以該憑證本身當 CA（`tls-ca-file`），註冊前用 `openssl` 檢查憑證 SAN 涵蓋 `clone_url` 的主機（IP 或網域），不涵蓋就中止並說明需重簽 — 憑證只有 CN 或缺該 IP 時，job 的 `git clone` 會憑證驗證失敗。
- 2026-10-22 Git SSH 埠用 2222，宿主機 sshd 的 22 不動 — 無人使用 SSH clone；沿用宿主機 sshd 搭 shim 轉發進容器的做法非官方支援，且改 sshd 或停用 sshd 會讓 `scp`／遠端管理失效。
- 2026-10-22 容器以 `docker.sh` 選單腳本用 `docker run` 啟動，不用 compose — 離線時少一個相依；每站只需換 tag 重建容器。
- 2026-10-22 Docker 的離線安裝從 `runner.sh` 抽成共用函式，`docker.sh` 與 `runner.sh` 共用 — 避免兩份 `docker.io` 相依解析邏輯。
- 2026-10-22 Runner 在遷移與升級到 19.5.1 穩定後才以 `runner.sh` 安裝（宿主機 deb、Docker executor、instance runner）— 尚未建置，沿用既有設計；順序放後面以免升級期間混入變因。
- 2026-10-22 機外備份由使用者手動複製，腳本只列檔案與大小並要求輸入確認字串 — 內網機的目的地因環境而異，腳本不猜。
- 2026-10-23 Docker 遷移 spec（ISSUE-001）隨佇列收斂刪除，promise 以測試中的 `PR-DKR-*` 註解為準；以下四項**尚未解決**，須在 Ubuntu 24.04 實機試跑後再決定，ADR 0001、0002 因此維持 `Proposed` — ①`apt purge gitlab-ce` 的 prerm／postrm 是否動到容器使用中的掛載目錄（若會，purge 改為停容器→purge→啟容器；`docker.sh` 的驗證步驟為此保留）；②UID 對齊、容器內 `gitlab-ctl backup-etc`、18.11 的 PostgreSQL 升級耗時與磁碟需求（決定 PR-DKR-14、21、23 的細節與警告門檻）；③`ufw` 擋不住 Docker 發佈的 80／443／2222，是否限制來源網段由使用者決定；④容器模式下 `backup.sh` 的還原項目未處理，需另立 spec。
